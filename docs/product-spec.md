I want you to treat the following as a product specification, not merely a prompt for generating a UI. First understand the complete system and its relationships. Then design the architecture and implement the application. Do not simplify away requirements merely because they are complex. Where implementation details are unspecified, choose the simplest robust solution consistent with the philosophy below. Do not add unrelated features. The result should be a genuinely functional local-first PWA, not a static prototype.

You are a senior product designer, UX architect, frontend engineer, backend/data architect, interaction designer, and product thinker.

Your task is to design and build a complete personal web application for a single user.

This is NOT a generic habit tracker.

This is NOT a productivity app for managing work.

This is NOT a generic Notion clone.

This is NOT a task-management app.

It should be understood as a PRIVATE PERSONAL OPERATING SYSTEM for one person.

The purpose of this application is to help the user:

1. Build and maintain a disciplined daily routine.
2. Track recurring habits and personal practices.
3. Track physical development, grooming, nutrition, exercise and gym performance.
4. Organize personal learning and intellectual development.
5. Remove the need to repeatedly decide what to read/watch/learn next.
6. Review each week honestly.
7. Understand where the user currently stands.
8. See historical trends and whether the user is genuinely improving over months and years.
9. Create a permanent personal record without destroying historical data.
10. Quietly hold the user accountable without notifications, nagging or gamification.

The core philosophy is:

    "The application should act as a mirror, a planner, a record and a compass."

It should show the user where they are.

It should show how the current day is going.

It should show how the current week is going.

It should show what is incomplete.

It should show whether the user is improving over time.

It should tell the user what learning resource is next.

It should make recurring commitments easy to execute.

It should require as little typing as possible during normal daily use.

The user should feel that the application belongs to them personally rather than feeling like a mass-market productivity application.

============================================================

Do not treat every piece of behavior as an identical checkbox.

- Meditation
- Hanuman Chalisa
- Reading
- Moisturiser
- Hair oiling
- Cardio
- Gym
- Creatine
- Chia seeds

B. ROUTINES
Ordered groups of actions.

Examples:

- Morning routine
- Pre-gym routine
- Evening routine

C. SESSIONS
Activities performed for some duration or with measurable execution.

Examples:

- Gym workout
- Reading session
- Learning session
- Meditation session

D. LOGS
Records of something that happened.

Examples:

- Breakfast
- Lunch
- Dinner
- Body weight
- Journal entry
- Workout sets

E. RESOURCES
Things the user wants to consume or learn from.

Examples:

- Book
- YouTube video
- PDF
- Article
- Podcast
- Course

F. TARGETS
Desired frequency or measurable objectives.

Examples:

- Gym: 5 sessions/week
- Cardio: 7 sessions/week
- Hair oiling: 2 sessions/week
- Reading/development: 7 sessions/week
- Meditation: 7 sessions/week

G. REVIEWS
Structured reflection over a period of time.

Examples:

- Weekly review
- Monthly review
- Long-term progress review

This distinction is extremely important.

The application should not simply contain 40 checkboxes.

8. DAILY SCORE
============================================================

The existing concept of daily score should remain.

Only habits/actions that are actually due today should contribute to today's denominator.

If a habit has a frequency of:

2 times/week

For example:

0/2

The app must distinguish:

- complete

- pending
- missed
- not due

rather than immediately treating incomplete actions as failures.

"Reading decreased from 6/7 to 4/7."
